## Как это работает

1. **Сигнал за минуту.** Медсестра, врач, пациент или родственник сканирует QR-код в больнице и пишет, что можно улучшить: свет в коридоре, похожие упаковки лекарств, сломанное оборудование. По-русски или по-узбекски, без входа и без имени.
2. **Обезличивание до сохранения.** Регулярные выражения убирают телефоны, номера палат и историй болезни, даты; Gemini убирает имена и размечает сигнал по концептуальной рамке ВОЗ (ICPS). В базу попадает только текст без имён.
3. **Повторы между больницами.** Сигнал превращается в вектор и присоединяется к закономерности, если 3 из 5 ближайших соседей похожи на него на 0,85 и выше. Одна больница видит случайность, система — общую причину.
4. **Сводка главврачу, а не дашборд.** Раз в неделю аналитик собирает с помощью ИИ короткую сводку по больнице: что повторяется и 1–3 меры, отсортированные по силе (RCA²). Слабые меры вроде «провести инструктаж» помечены.
5. **Решение и реакция.** Главврач принимает меру со сроком или отклоняет с причиной, потом отмечает «Выполнено». Райздрав видит, как быстро больницы читают сводки и выполняют меры, — и никогда не сравнивает их по числу сигналов.

## Приватность — это и есть продукт

- Исходный текст нигде не хранится и не логируется: он живёт только в памяти запроса.
- В потоке сигнала нет входа, cookies, IP и user-agent. Полей для имён нет — только необязательная роль.
- Хранится только дата и смена (день/ночь), без точного времени.
- Разрез по отделению показывается только для групп от 5 сигналов.
- ИИ предлагает, человек подтверждает: любую разметку можно поправить.

| Кто | Что видит |
| --- | --- |
| Автор сигнала | Только форму по QR — аккаунта нет никогда |
| Аналитик | Обезличенные сигналы, собирает сводки |
| Главврач | Сводки и меры своей больницы |
| Райздрав | Скорость реакции своих больниц, без текстов и рейтинга |

В демо экраны ролей открыты; в пилоте — вход по приглашению для каждой роли.

| Что | Результат |
| --- | --- |
| Тип события | 89% |
| Последствия для пациента | 85% (100% в пределах ±1 уровня) |
| Дошло ли до пациента (near miss) | 97% |
| Заложенные закономерности | 11 из 11, 7 из 7, 5 из 5 — и одна незаложенная (5 сигналов про ампулы) |

Проверка: `npm run eval`. На реальных данных цифры будут ниже — их измерим на пилоте.

## Безопасность

- Ключи Gemini и Supabase только на сервере; RLS включён без политик — из браузера база недоступна.
- Лимит запросов в приложении (без IP) и правило фаервола Vercel на POST: 30 в минуту.
- Лимит расходов на Gemini; сигнал до 4000 знаков.
- Текст сигнала — данные, а не инструкции: у модели нет инструментов, ответ проверяется JSON-схемой и zod, id в сводке фильтрует код.
- Функции Vercel и база Supabase — в Сеуле (Южная Корея в перечне стран ПКМ №415).

## Стек

Next.js 16 (App Router, server actions) · TypeScript · Tailwind CSS 4 · Google Gemini (`@google/genai`: анализ, эмбеддинги, разбор, сводка) · Supabase Postgres + pgvector · Vercel.

## Запуск локально

```bash
npm install
cp .env.example .env.local   # ключи Gemini и Supabase
```

1. Создать проект Supabase и выполнить в SQL Editor [supabase/schema.sql](supabase/schema.sql), затем [supabase/migration_v2.sql](supabase/migration_v2.sql).
2. Загрузить синтетические сигналы и найти закономерности:
   ```bash
   npm run seed
   npm run patterns
   ```
3. Запустить:
   ```bash
   npm run dev
   ```

Скрипты: `npm run demo:reset` — вернуть демо в исходное состояние (перед каждым показом), `npm run eval` — точность, `npm run smoke` — 5 текстов через весь конвейер, `npm run typecheck`. Перезапись видео — [docs/demo/README.md](docs/demo/README.md).
